# Teensy 4.0 + GY-9250 (MPU-9250, ICF1068)

VS Code에서 펌웨어를 업로드하고, Python으로 데이터를 받아 기존 OAK-D 대시보드에 표시하는 실험용 프로젝트입니다. **실제 보드 업로드·정확도 검증은 아직 하지 않았습니다.**

## 무엇을 보여 주나

- 로봇이 **바라보는 방향**: 중앙 화살표, 각도, 8방향. 후진할 때 실제 이동 방향과 반대일 수 있습니다.
- 로봇의 **3D 자세**: roll(전후축 회전), pitch(좌우축 회전), yaw(수직축 회전)를 직육면체 모형과 숫자로 표시합니다. 원형 화살표는 위에서 본 yaw만 표현하므로 뒤집힘·기울기는 3D 모형을 확인합니다.
- 기본: 시작 방향을 0°로 하는 상대 방향. 오른쪽 90°, 뒤 180°, 왼쪽 270°. 자이로 누적 오차로 방향이 서서히 틀어집니다.
- 자력계 보정 파일을 적용하면: 자기 북쪽 기준 북/북동/동/남동/남/남서/서/북서. **진북이 아니며**, 모터·철근·자석 때문에 틀릴 수 있습니다.
- 가속도: 자세 추정으로 중력을 제거한 로봇 좌표 X/Y/Z, 단위 m/s².
- 속도: 중력 제거 가속도를 적분한 3차원 속력, 단위 m/s.
- 변위: 속도를 적분한 세계 좌표 X/Y/Z, 단위 m. **바퀴 오도메트리나 정확한 위치가 아닙니다.**

9축이라고 속도·위치를 직접 측정하는 것은 아닙니다. 작은 가속도 편향과 자세 오차도 적분하면 커집니다. 약 0.5초 동안 각속도와 중력 제거 가속도가 모두 작으면 지상 로봇이 정지했다고 가정하여 속도를 0으로 보정합니다. 하지만 일정 속도로 부드럽게 움직이는 것과 정지 상태는 IMU만으로 확실하게 구분할 수 없으므로 잘못 0으로 판단할 수도 있습니다. 현재 값은 짧은 구간 실험용이며 제어·안전·정밀 위치·보수비 산출 근거에 쓰면 안 됩니다. 실제 주행에는 바퀴 엔코더/시각 오도메트리 등 외부 관측과 융합해야 합니다.

## 1. 배선 (전원을 끈 상태에서)

| Teensy 4.0 | GY-9250 |
|---|---|
| 3.3V | VCC (보드의 3.3V 입력 지원 확인) |
| GND | GND |
| 18 / SDA | SDA |
| 19 / SCL | SCL |
| GND | AD0 (0x68 선택, 3.3V이면 0x69) |
| 3.3V | NCS/CS가 노출되어 있다면 연결 (I²C 모드) |

INT, FSYNC, EDA, ECL 등 나머지 핀은 이 예제에서 연결하지 않습니다. 보드 인쇄명을 확인하고 연결하세요. Teensy는 USB 데이터 케이블로 PC에 연결합니다. **Teensy 4.0 신호핀은 5V를 허용하지 않습니다.** 모듈의 VIN 허용 전압과 I²C 신호 전압은 별개이므로 5V 풀업에 연결하면 안 됩니다. SDA/SCL 풀업이 모듈에 없는 경우 3.3V로 각각 약 4.7kΩ 풀업이 필요할 수 있습니다. 실제 모듈 회로/전압을 먼저 확인하세요.

기본 장착축은 **X=로봇 전방, Y=왼쪽, Z=위쪽**입니다. 보드의 축 표시와 칩 데이터시트 축을 확인하세요. 옆으로 90° 돌려 설치했다면 `--axes 2,-1,3`처럼 설정할 수 있습니다(로봇 X=센서 Y, 로봇 Y=-센서 X). 오른손 좌표계만 허용합니다. 자력계 축은 펌웨어에서 가속도/자이로 축으로 먼저 정렬합니다. 센서는 단단히 고정하고 모터·전력선·강철 부품과 가능한 거리를 확보하세요.

출처: [PJRC I²C 핀 표](https://www.pjrc.com/teensy/td_libs_Wire.html), [Teensy 4.0 전압 제한](https://www.pjrc.com/store/teensy40.html), [TDK MPU-9250 데이터시트](https://invensense.tdk.com/wp-content/uploads/2015/02/PS-MPU-9250A-01-v1.1.pdf).

## 2. VS Code에서 펌웨어 업로드

1. VS Code에서 이 `imu` 폴더를 엽니다.
2. 공식 **PlatformIO IDE** 확장을 설치합니다.
3. `platformio.ini`의 `teensy40` 환경으로 Build 후 Upload 합니다. 첫 빌드는 Teensy 도구 다운로드가 필요합니다.
4. Teensy가 잡히지 않으면 USB 데이터 케이블을 확인하고 보드의 Program 버튼을 누릅니다.
5. Serial Monitor에서 `chip: MPU9250`, `mag_present: true`에 해당하는 JSON이 나오는지 확인한 뒤 **Serial Monitor를 닫습니다.** Python과 같은 COM 포트를 동시에 열 수 없습니다.

PlatformIO 터미널 명령은 `pio run`, `pio run -t upload`입니다. [공식 Teensy 4.0 설정](https://docs.platformio.org/en/latest/boards/teensy/teensy40.html)을 사용했습니다. 이 PC에는 현재 PlatformIO/Arduino CLI가 없어 펌웨어 빌드는 미검증입니다.

펌웨어는 WHO_AM_I로 MPU9250(0x71), MPU9255(0x73), MPU6500(0x70)을 구분하고 AK8963 자력계도 별도 확인합니다. 상품명이 GY-9250인데 `MPU6500` 또는 자력계 없음으로 나오면 배선·보드 실물을 확인하세요. MPU6500은 자기 북쪽을 측정하지 못합니다.

## 5. 자기 북쪽 기준으로 쓰기 (선택)

기본 상대 방향으로 먼저 배선·축 방향을 확인합니다. 실제 브리지를 켜 둔 상태로 **두 번째 IMU 가상환경 터미널**에서:

```powershell
python calibrate_mag.py --seconds 60
```

센서를 세 축 모두에 대해 천천히 다양한 각도로 회전시킵니다. 평면에서 한 바퀴만 돌리는 것으로는 충분하지 않습니다. 로봇을 안전하게 회전시킬 수 없다면 무리하게 들거나 운전 중 회전하지 마세요. 가능하면 최종 장착 상태의 고정 자기장 영향을 반영하되 안전을 먼저 확보하세요. 모터 전류에 따라 바뀌는 자기장이나 터널 철근의 영향은 이 보정으로 제거할 수 없습니다.

완료되면 `mag_calibration.json`이 생깁니다. 기존 파일을 덮어쓰지 않으므로 재보정 시 `--output mag_calibration_v2.json`처럼 새 이름을 사용합니다. 브리지를 Ctrl+C로 종료하고:

```powershell
python bridge.py --port COM5 --mag-cal mag_calibration.json
```

정지 보정이 끝날 때 유효한 자기장도 확보되면 북/북동/… 표시로 바뀝니다. 확보하지 못하면 상대 방향으로 남으므로 메시지를 확인하세요. `--axes`를 사용했다면 보정 수집 때와 재시작 때 반드시 같은 값을 사용합니다.

보정은 min/max 기반 하드아이언 오프셋 + 축별 스케일 보정이며, 정밀 타원체 보정이 아닙니다. 자기장 크기와 급격한 방향 불일치 검사를 하지만 **간섭을 모두 판별하지는 못합니다.** 이후 자기장이 거부되거나 끊기면 자이로로 잠시 유지하고 경고합니다. 모터 ON/OFF, 정지/회전, 실제 터널에서 다른 기준과 비교해야 합니다. 기준을 다시 설정하려면 브리지를 재시작합니다.

## 7. ROS2 확장 시작점

ROS2가 설치·활성화된 환경에서 Python 브리지와 함께:

```bash
python3 ros2/imu_bridge_node.py
ros2 topic echo /imu/data
```

- `/imu/data`: `sensor_msgs/Imu`, 자세 + 바이어스 보정 각속도 + **중력 포함** 가속도.
- `/imu/mag_raw`: `sensor_msgs/MagneticField`, 장착축 변환된 보정 전 자기장을 Tesla로 변환.
- 자기 모드 세계 좌표는 NWU에서 **자기 ENU**로 변환합니다. 상대 모드는 yaw 원점이 임의이며 동쪽/북쪽이라고 해석하면 안 됩니다.
- `imu_link`는 **로봇 축으로 재정렬한 가상 센서 프레임**입니다. 향후 TF는 이 재정렬을 중복 적용하지 말고 실제 센서 위치 오프셋을 반영해야 합니다.
- 측정 공분산은 실측하지 않아 IMU의 0 배열로 **unknown**을 표현합니다. 정밀 필터에 넣기 전 별도 측정/설정이 필요합니다.
- 데모 데이터는 ROS2에 기본 발행하지 않습니다. 시험 시에만 `--ros-args -p allow_demo:=true`.
- 실험 오도메트리는 기본 OFF. 필요할 때만 `--ros-args -p publish_experimental_odom:=true`를 지정하면 `/imu/odometry_experimental`에 발행합니다. 공분산은 매우 큰 임시값이며 정량적 오차 모델이 아닙니다. 내비게이션 필터에 넣지 마세요.
- `odom → base_link` TF는 발행하지 않습니다. 최종 오도메트리는 엔코더 등의 정보와 융합한 노드가 담당하도록 남겨 두었습니다. 재보정 때 실험 좌표계가 재설정됩니다.
- 기본 같은 PC의 localhost 연결입니다. WSL/다른 PC에서 ROS2를 돌릴 경우 네트워크 구성이 추가로 필요합니다. 이 프로젝트는 외부 네트워크 노출을 자동 설정하지 않습니다.

ROS2 스크립트는 미래 확장용 단독 실행 어댑터로, ROS2 런타임 연결은 아직 미검증입니다. [ROS2 Imu 메시지](https://github.com/ros2/common_interfaces/blob/rolling/sensor_msgs/msg/Imu.msg), [Odometry 메시지](https://github.com/ros2/common_interfaces/blob/rolling/nav_msgs/msg/Odometry.msg), [REP-145 센서/좌표계 규약](https://github.com/ros-infrastructure/rep/blob/master/rep-0145.rst)을 참고했습니다.

보정 전 자이로 영점 오차를 움직임으로 오인하지 않도록, 최근 200샘플 전체의 변동 폭으로 안정성을 검사합니다. 큰 각속도/가속도 이상은 계속 차단합니다. 안정적인 저속 회전은 영점 오차와 구별할 수 없으므로 사용자가 로봇의 실제 정지를 보장해야 합니다. 정지 가속도 크기가 중력에서 크게 벗어나면 방향 표시를 허용하되 경고를 표시합니다. 한 자세만으로 3축 가속도 오프셋/스케일을 알아낼 수 없으므로 가속도 원값을 강제로 중력에 맞추지 않습니다. 이 경우 가속도·속도·변위는 특히 신뢰할 수 없습니다. 수정 적용에는 bridge.py 재시작만 필요하고 Teensy 재업로드는 필요 없습니다.
